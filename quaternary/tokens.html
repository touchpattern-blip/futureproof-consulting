Why your token bill doesn't seem logical

The billing physics of agentic AI, and how a local-first setup changes the math. Companion to the Quaternary.
The one-sentence answer: an agent's bill scales with context size × number of steps, not with the amount of work you asked for. Cloud agent platforms grow both silently, while a flat-rate, local-first setup caps one and shrinks the other.

1. The mental model everyone starts with, and why it's wrong

Intuition says: "I sent a few prompts and got a few answers. Small bill." That model is right for a chat window and catastrophically wrong for an agent.

Every time an agent takes a step - runs a command, reads a file, calls a tool: the platform sends the model the entire conversation so far: your instructions, every file it has read, every tool result, every previous thought. The model is stateless; the only way it "remembers" the session is by being re-fed all of it, every single step. On metered billing, you pay for that re-feed every time.

So a session that feels like "one request" is actually:

step 1:  30,000 tokens in  → small answer out
step 2:  34,000 in (everything again + new results)
step 3:  41,000 in
  ...
step 60: 160,000 in
total input billed: ~5,000,000 tokens - for one afternoon's task

Output tokens (the text the model writes) are usually a rounding error next to this. The bill is dominated by input re-reads, which is why it "doesn't seem logical": the costly thing is invisible.

2. The three multipliers cloud agent platforms add

Context stuffing

Repo-connected tools (GitHub integrations, cowork platforms) helpfully pre-load context: file trees, diffs, open issues, prior threads. Convenient. And every one of those tokens rides along on every subsequent step. A 40k-token preamble on a 50-step session is 2M tokens of input before you've asked for anything.

Long-lived threads

Continuing yesterday's conversation feels natural. On metered billing, it means yesterday's whole transcript is now the entry fee for every new step today. Threads that never reset are compound interest against you.

Loops you don't see

Agents retry, re-read, and self-correct. A flaky test that takes four attempts bills four contexts. CI-triggered agents can run with nobody watching. None of this is malicious; it is simply that metered billing turns every inefficiency directly into money.

3. What the flat-rate + local-first setup does differently

Our system runs on the same frontier models. The bill is different for four architectural reasons, in order of impact:

a. Flat-rate subscription for the interactive loop

The conversational agent runs under a monthly plan (Claude Code on a Max subscription), not per-token API billing. The re-feed physics still exist, but they burn against a flat monthly price with usage limits, not an open meter. Heavy month, light month: same bill. For anyone using an agent as a daily driver, this alone is usually the difference between $100-200/mo fixed and a metered bill that swings into four figures.

Honest caveat: flat plans have ceilings too. We've hit monthly limits mid-task and had agents die on them. The answer is the same discipline below, not pretending limits away.

b. The nervous system runs on zero tokens

Most of what our system does per day never touches a model:

  • Memory recall is a local keyword index (BM25 search over notes) injected as a few hundred tokens - not an LLM call, and not a giant history dragged into context.
  • Watchers, health checks, backup verification, notification guards: shell scripts and cron. They alert a phone directly. Zero tokens, ever.
  • Status checks that platforms would do with an agent ("did the backup run?") are grep against a log file.

Rule of thumb: the model is reserved for judgment. Anything mechanical (polling, diffing, counting, verifying, formatting) is code, because code costs nothing per run.

c. Context discipline: pointers, not payloads

  • Memory lives in files, not in the conversation. The agent is told where things are ("the device quirks are in this note") and fetches only what the task needs. Nothing rides along "just in case."
  • Sessions reset deliberately. A close ritual saves conclusions to disk, then the context is cleared. Tomorrow starts at 10k tokens, not 400k.
  • Long work is delegated to fresh sub-agents with a scoped brief: a 2k-token instruction instead of a fork of the whole conversation. They finish, verify, and return a summary, not a transcript.
  • Compaction squeezes long threads into summaries instead of letting them compound.

d. Local models for the background tier

A $250 used GPU in a 2010 tower runs a 9B-parameter model entirely in VRAM. It handles verification passes, memory consolidation, and semantic checks: the high-volume, low-difficulty calls that would otherwise leak money continuously. Marginal cost per call: electricity.

4. What Pedro can actually do, in order of payoff

  • 1. Match the billing model to the usage. Daily-driver agentic use on a meter is the wrong instrument. A flat plan (or a hard monthly budget cap if staying on API) converts an unbounded risk into a fixed cost.
  • 2. Kill the long-lived thread habit. Finish a task, extract what mattered into a file, start fresh. This is the single biggest metered-bill lever that costs nothing.
  • 3. Audit what gets pre-loaded. If the platform stuffs the repo into context, scope it: one directory, one diff, one issue. Every preamble token is billed once per step, not once.
  • 4. Move the mechanical steps out of the loop. Tests, linting, log-watching, retries: run them in CI/scripts and hand the agent results, not the job of babysitting them.
  • 5. Use the smallest model that survives the task. Frontier models for judgment, small/cheap ones for classification and glue. Tiering is often a 10× cost difference at identical outcomes.
  • 6. Read the usage dashboard weekly. Whatever the platform, it will show that a handful of sessions consumed most of the spend. Fix the shape of those sessions specifically.
The deeper point: this is the local-first thesis in economic form. Cloud intelligence is worth paying for: it is genuinely brilliant. But intelligence-per-dollar collapses when architecture makes the model do work a shell script could do, and remember things a file could hold. Rent the brilliance. Own the plumbing.
