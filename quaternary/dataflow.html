Where your prompt actually goes

The data flow behind every AI chat window, and the hybrid we run instead. Companion to the Quaternary.
The one-line audit: a chat window is four hops, and every setup is defined by who owns each hop. The browser tab tells you nothing; the same window can front a datacenter or your own laptop. Follow the POST.

1. The four hops

HOP 1
Interface
What renders the window. A browser tab is just a renderer; it implies nothing about where the model lives.
→
HOP 2
Transport
Where the request goes when you hit enter. Localhost, LAN, or someone's datacenter.
→
HOP 3
Inference
Whose silicon runs the model. Every token is plaintext at this hop, in every setup, always.
→
HOP 4
Storage
Who keeps the record: your disk, their retention policy, or nothing at all.

"Is my data private" reduces entirely to hops 2 through 4. Everything else is interface cosmetics.

3. Where censorship lives

Refusals are not one switch. They are three, at three different hops:

LayerWhat it isCloud productLocal open weights
The weightsRefusal behavior trained into the model itselfTheirs, fixedYour choice of build, including uncensored variants
The system promptHidden instructions wrapped around every messageTheirs, invisible to youYours, or none
The output filterModeration layer scanning responses after generationTheirs, non-negotiableDoes not exist

Local open weights is the only column where all three switches are yours. That is the technical meaning of "no overlords": nobody upstream can revoke, throttle, filter, or retrain the tool out from under you.

4. The hybrid we actually run

Our system is deliberately split into three tiers, and the split is the design:

Rented judgment frontier model, metered trust

Operator terminallaptop
→the FULL working context re-sends on every step
Frontier model APIthe highest-capability reasoning, rented
→
Transcript of recordstored on the laptop, not in a vendor chat history
The rule that matters: whatever the agent reads into a session transits with that session, every step, until it ends. So the perimeter is not "which machine is the file on"; it is "was it read into a rented-lane conversation." Discipline: hand the agent pointers, not payloads.

Owned memory cloud-free at rest

Life archive + noteslaptop disk, plain files
Reasoning memory DBhome server
←→derived over the LAN
Local model on own GPUwrites memory conclusions nightly
Every memory layer lives on owned hardware. A local open-weights model does the nightly derivation, so even the system's remembering is cloud-free. Excerpts transit only when recalled into a rented-lane session.

The mechanical layer zero tokens, zero cloud

Watchers, backups, guards, health checksshell scripts + cron on owned machines
→
Alerts to a phoneno model involved anywhere
Most of what the system does per day never touches AI at all. The model is reserved for judgment; everything mechanical is code, because code costs nothing per run and leaks nothing per run.
The verdict in one sentence: judgment is rented from the frontier, the record and the memory are owned outright, and the mechanical layer never touches a model. If the rented layer is ever revoked, throttled, or filtered, the system loses capability, not continuity. Most setups are the inverse: the memory lives in the vendor's chat history and the local machine holds nothing.

5. The traps that fool people

Local UI, cloud brainA self-hosted chat interface with a vendor API key pasted in looks pixel-identical to fully local. Follow the POST, not the interface.
Local brain, leaky toolsGive a local model web search or a cloud-backed tool, and conversation-derived content rides inside every tool call.
App-level telemetryInference can be local while the app phones home with session counts and model names. Closed-source runners are trust-their-claim; open-source runners are verifiable.
"Private" enterprise deploymentA cloud-hosted model under an enterprise contract is contractually private, not architecturally private. Different trust class than weights on your own desk.
The 60-second audit, for any setup, anyone's: open the browser's network inspector, send a message, and read where the request goes. Everything else is marketing.
